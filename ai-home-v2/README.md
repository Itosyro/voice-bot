# ДВИЖ — AI Home v2, изолированный preview

Продолжение ветки `codex/dvizh-ai-home-v2-2026-09-05` поверх коммита
`272e475b98481a949b4511aae11af14fad542860` (preview-first + isolation CI).
Сохранены пустой idle, контекстный ручной маршрут и удержание до отпускания
без таймера из параллельных коммитов `1bba0cf` / `9bd3df6`.
Условия изоляции из `272e475` перенесены в расширенные контрактные и браузерные тесты.

## Границы текущего этапа

Отдельная страница `/ai-home-v2-preview.html`. Рабочая `/` НЕ заменяется.
На экране только ИИ, состояние, текстовый/голосовой ввод и последний ответ.
Нет задач, карточек proposals, чек-инов и нижнего меню.
В режиме preview старый интерфейс остаётся на `/`. После отдельного явного
переноса AI на главную ручной интерфейс находится на `/manual.html`.

Не подключаем старые `app.js`/`styles.css`, не меняем service worker,
не удаляем кеши, не регистрируем новых workers, не перезапускаем сервисы.
Анимация выполнена в CSS. Таймеры ограничены ожиданием ответа API,
HTTP-дедлайном. Удержание измеряется на отпускании по performance.now(). В покое постоянного опроса нет.

## Что исправлено после исходной версии

- Удалена очистка общих кешей и отмена регистрации service worker при запуске.
- Вместо немедленной замены index.html установщик создаёт только preview.
- По умолчанию установщик ничего не записывает; payload берётся из локального
  проверенного checkout, а не из старого зафиксированного remote ref.
- Один сетевой процесс на видимый экран, HTTP-дедлайн 15 секунд,
  ограниченное ожидание ответа, отмена при уходе и восстановление при возврате.
  Поздние результаты старой сессии не перерисовывают новую.
- Новая page-session визуально всегда начинается пустой: сохранённый ответ из
  предыдущего диалога не показывается при входе или обычной перезагрузке.
  Если при входе уже есть pending/processing запрос, экран продолжает именно его
  и показывает только ответ, который завершил наблюдаемый текущей страницей запрос.
- Повторный клик не дублирует запрос. При 409 перечитывается свежая ревизия.
  После неоднозначного ответа PUT сохранённый id проверяется перед повтором.
- Ошибка, отмена или промежуточный результат распознавания не отправляют
  старый черновик. Запись можно отменить Escape; при уходе она прерывается.
- Высота подстраивается под visualViewport по событиям, без DOM-циклов.
  Добавлены видимый фокус, корректный hidden и prefers-reduced-motion.

## Совместимость с существующим мостом

Используется существующий same-origin `/api/state`: GET и PUT с baseRevision.
Перед записью берётся свежая копия состояния. Клиент изменяет только
`aiHomeRequests`, `aiHomeMessages`, `aiHomeStatus`; остальные поля сохраняются.
Если уже есть pending/processing запрос, новый не добавляется.

Серверный `hermes-control-v1/dvizh_ai_home_bridge.py` не изменён.
Ключи провайдера не попадают в клиент. Нет прямого вызова Hermes из браузера
и нет автоматического принятия proposals. Подтверждение остаётся в ручном
интерфейсе. Живой сервер и его текущее состояние здесь не считаются проверенными.

## Ручной режим и голос

Удержать орб примерно 1,1 секунды, ввести `/manual` или нажать Alt+M.
Постоянной кнопки меню на AI-экране нет; подсказка доступна скринридеру.

Голос использует SpeechRecognition/webkitSpeechRecognition браузера;
доступность и разрешение микрофона зависят от браузера и устройства.
Текстовый ввод остаётся запасным вариантом. Реальный звук, Android-клавиатура
и установленная PWA требуют проверки на устройстве, не только эмуляции размеров.

## Проверки без сервера

Из корня checkout:

```sh
bash -n install-dvizh-ai-home-v2.sh
node --check ai-home-v2/ai-home-v2.js
node --test tests/ai-home-v2/*.test.cjs
```

Node-тесты используют детерминированный DOM/event harness и временные каталоги.
Они проверяют жизненный цикл, таймауты, 409/401/403, идемпотентность отправки,
ошибки речи, сохранность данных, повторную установку и откат при сбое записи.
Это НЕ замена настоящему браузеру.

Полный браузерный smoke test в CI запускается с локальным HTTP origin,
тестовым manual.html/service worker и мокированным API, без production-секретов:

```sh
python -m pip install playwright==1.57.0
python -m playwright install chromium
python tests/ai-home-v2/browser_test.py
```

При запрете навигации средой доступен явно ограниченный режим:

```sh
DVIZH_BROWSER_IN_MEMORY=1 python tests/ai-home-v2/browser_test.py
```

Он проверяет реальный Chromium DOM, стили и взаимодействия с API в памяти,
но пропускает два теста, требующих настоящего origin: переходы/back и
сохранность зарегистрированного service worker/кеша. CI этот флаг НЕ задаёт.
Скриншоты сохраняются в `test-results/`; их не надо коммитить.

## Установка preview — только после проверки checkout и состояния сервера

Не запускать старый установщик через `curl | sudo bash`.
Из проверенного checkout на сервере:

```sh
bash install-dvizh-ai-home-v2.sh --check
```

Это только проверка файлов и здоровья уже установленных сервисов.
Без аргументов поведение такое же. Лишь после проверки оператором:

```sh
sudo bash install-dvizh-ai-home-v2.sh --install-preview
```

Создаются только `/ai-home-v2-preview.html` и отдельные JS/CSS. `manual.html`
не создаётся и не перезаписывается; переход в ручной режим ведёт на стабильную `/`. SHA-256 проверяет неизменность index.html/app.js/styles.css/sw.js
и существующего manual.html. Перед записью сохраняется backup preview;
сбой записи откатывает только затронутые preview-файлы.

Нет правки nginx/PWA-манифеста, установки Hermes, изменения БД,
отключения service worker или рестартов. Открытие preview на реальном домене
может зависеть от действующих правил раздачи статики и кеширования; это нужно
проверить, а не чинить глобальным сбросом кеша.

## Совместимость установщика и отложенный перенос на главную

Существующие явные `DVIZH_AI_HOME_V2_MODE=preview|promote` сохранены; добавлены
`--check`, `--install-preview` и `--promote`. Без аргумента и без явно заданной
переменной режима выполняется ТОЛЬКО check. Источник — локальный checkout,
без загрузки старого payload из зафиксированного remote ref.

Promote не запускается автоматически. Он требует установленный preview и
побайтово совпадающие HTML/JS/CSS; различающийся существующий manual.html
не перезаписывается. Повторная операция не копирует AI-экран поверх manual.
Если главная уже AI, preview-установка отклоняется, чтобы не обновлять
используемые главной assets под видом изолированного тестирования.
Это технические ограничения, а не замена проверке на телефоне и решению владельца.
В этой сессии перенос на главную и установка на живом сервере НЕ выполнялись.

## Результаты локальной проверки

- 67 Node-тестов: прошли (51 клиент + 16 установщик), включая совместимость

  здесь он не объявляется успешным заранее.
